## Problem Statement

### Problem 1: Too Many Tracking Surfaces (13 files, 5 stale)
Framework grew organically from 3 files to 13. Maintenance cost exceeds capacity of solo researcher + AI. Proof: 5/13 files stale within 3-5 days.

### Problem 2: Session Continuity Loss (the bigger problem)
Claude loses work context in two ways:
- **Within session:** Compact context makes Claude "pikun" — loses nuance, drifts
- **Across sessions:** Handoff document (NEXT_SESSION_BRIEF) is narrative/lossy. Claude reads it as background context, not as a work contract. Result: doesn't continue yesterday's unfinished work, starts something new or re-does finished work. User must re-direct — and sometimes user also forgets, so work gets permanently dropped.

**Root cause:** No structured mechanism to track WORK STATE (what's half-done, what's the exact next step, what context would be lost).

---

## Proposed Solution

### A. Session Continuity: `docs/WORKSTATE.md` (NEW)

A small, structured, machine-readable file that captures **unfinished work** — not history, not strategy, not accomplishments.

**Format:**
```markdown
# Work State — Updated: [date]

## IN PROGRESS (must continue next session)
- [ ] [Task]: [one-line description]
  - Files: [exact paths being modified]
  - Next action: [specific, concrete — not "continue working on"]
  - Context: [anything that would be lost in compaction]

## BLOCKED (waiting on external)
- [ ] [Task]: [what's blocking]

## SESSION PROMPT
[Copy-paste prompt for next session — replaces NEXT_SESSION_BRIEF section 6]
```

**Protocol (add to CLAUDE.md):**
1. **Session start:** Read `docs/WORKSTATE.md` FIRST, before user gives any instruction. Explicitly acknowledge in-progress items. Continue them unless user redirects.
2. **Session end:** Update WORKSTATE.md with all unfinished items + concrete next actions. This is the MINIMUM required before ending.
3. **Mid-session (after compact context):** If context was compacted, re-read WORKSTATE.md to re-anchor on what's being worked on.
4. WORKSTATE.md is ephemeral — it captures work state, not history. History stays in JOURNAL.md.

**Why this works better than NEXT_SESSION_BRIEF:**
- Structured, not narrative → Claude can't skip items
- Focused on UNFINISHED work → not a "what we did" report
- Concrete next actions → not vague "priorities"
- Small (<50 lines) → easy to read, hard to misinterpret
- Includes session prompt → replaces NEXT_SESSION_BRIEF's copy-paste section
